## Bestilling og styring

Brukerens fullstendige bestilling er bevart i
[promptloggen](../prompts/session-01a14a36-f7b5-7882-a06f-f7b38c8ebdcb.jsonl).
Hovedagenten orkestrerer tre sekvensielle overleveringer: implementering av
Story 1.3, separat BMAD code review med retting/verifikasjon, og deretter
implementering av Story 1.4 bare dersom 1.3 er godkjent og `done`.

Bare én agent har skriveansvar om gangen. Eventuelle underreviewere får
utelukkende lesetilgang som arbeidsinstruks. Hovedagenten redigerer og
committer bare mellom overleveringene. Ingen push, betalte kall eller
implementering av senere stories er autorisert. Nye produkt-/arkitekturvalg
eller endring av låste grunnlag stopper den berørte kjeden.

Den eksplisitte implementeringsbestillingen gjelder tekniske storyspesifikasjoner
som utelukkende konkretiserer eksisterende godkjent grunnlag. Den erstatter
ingen readiness-port eller nødvendig menneskelig beslutning. BMAD build
utføres til implementeringsverifikasjon; separat review av 1.3 utføres i fase 2.
Story 1.4 avsluttes som `review`/`in-review` uten egen code review etter
brukerens uttrykkelige avgrensning.
