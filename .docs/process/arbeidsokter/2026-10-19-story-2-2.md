## Arbeid og rutinevalg

Låst Node 24.21.0-distribusjon fra Story 1.1 ble gjenbrukt sammen med npm
11.19.0. PDF.js 6.4.299 ble installert eksakt, og låsfilen gjenskapt med
ren npm ci. Ingen pin eller produktstakk ble endret. Midlertidig Python
3.12.14-miljø i `/private/tmp/` fikk ReportLab 4.4.4, pypdf 6.1.3 og
PyMuPDF 1.26.6/Pillow 13.0.0 for fixturegenerering og visuell kontroll.
Poppler manglet, så tilgjengelig PyMuPDF ble brukt som renderer. PDF-skillen
ble lest, og dens mark_artifact_operation_started kjørt én gang før første
generering med forventet antall ti PDF-navngitte fixturefiler.

Først ble adapteruavhengig `expected.json` skrevet med F1–F4-funn, dokument/
PDF-side/grad/funntekst/trykt sidenummer, avklaringsstatus og låste finansdata.
F3s leie forble null. TG2-teksten «Slitt overflate på baderomsgulv» er et
fiktivt rutinevalg innen godkjent fasitplassering, ikke en ny produktregel.
Deretter ble en deterministisk generator skrevet som ikke leser fasiten eller
adapterretur. Ti filer og eget bytehashinventar ble generert. Ingen adapter
eller faktisk modell er kalt, og ingen lagret adapterretur er lagt inn.

Backend fikk ett bytesbasert format-/side-/hashsteg. Navn er bare metadata;
hash og beholdte bytes stammer fra et snapshot før asynkron parserbruk.
Parseren får separat kopi. Formatgodkjenning fikk eget internt
`format-validated`-utfall for å holde det adskilt fra lesbarhet og completed
analyse. Dokumentfeil gjenbruker 2.1-kontrakten; ingen konkurrerende
HTTP-/adapterkontrakt eller tekstuttrekksmetode ble opprettet.
PDF.js-loadingtask destrueres i finally på både suksess og feil.

## Kvalitetssikring, funn og retting

17 integrasjoner med ekte PDF.js/bytes etterprøver 30/31, ikke-PDF/skadet/tom,
SHA/navn/endrede bytes, bevarte originaler ved Buffer-slice/caller-mutasjon,
tekstløs gyldig container, reell worker-destruksjon og F1–F4-fasit/RT-5.
Første typecheck avdekket at `isEvalSupported` ikke er en option i den låste
PDF.js-versjonen; den ble fjernet og type/lint/test/build kjørt på endelig kode.

Uavhengig pypdf kontrollerte alle funn/navn/filsider og tekst på alle 61
grensesider. Alle 16 F1–F4-sider ble rendret og visuelt inspisert som kontaktark,
inklusive norske tegn, kildeplassering og F4s filside 4 / trykt side 2.
Regenerering ga byte-identiske ti filer og hashmanifest. Kontrollen er
agentens faktiske inspeksjon, ingen påstand om en separat menneskelig review.

Ren npm ci, målrettet PDF-integrasjon, full Vitest 292/292, typecheck, lint
og build bestod. Eksisterende appregresjon ble først sperret av lokal
sandbox-loopback og deretter manglende browser i standardcache. Godkjent
loopback-eskalering og den dokumenterte browserstien fra Story 1.2 ble brukt
ved ny kjøring: **41/41 bygget demo og 2/2 dev bestått**. Dette endret ingen
produktkode/pin.

[Verifikasjonen](../../implementation-artifacts/story-2-2-verifikasjon.md)
samler konkrete kommandoer/resultater, AC-spor, bilder og bevisgrenser.
Låste planer/specs/reference er uendret mot baseline
`f8167fd1f81f377ef97ce5f6a0d46a53d10312dd`. README og backend-/fixture-README
beskriver faktisk status og kjøring.

## Overlevering

Story 2.2 avsluttes på **in-review / review** med fire egenverifiserte AC.
Root overtar skriveansvaret ved overlevering, kontrollerer diff og lager lokal
commit uten push. Ingen integrert code review eller done er utført. R2 er
fortsatt åpen, og 2.3 står på backlog. Format-/fixturebevis er ikke
lesbarhetsgodkjenning, S2-modelltreff eller S5/S6. Ingen produkt-/arkitektur-
avgjørelse eller reell blocker ble funnet innen denne leveransen.

## Hovedagentens avslutningskontroll

Etter eksplisitt retur av skriveansvar ble modul, alle integrasjonstester,
generator/fasit og dokumentasjonsdiff kontrollert mot fire AC og hele
I/O-matrisen. Alle rader er prøvd og bestått; F4-kontaktarket ble også
åpnet og kontrollert av hovedagenten. De fem oppgavene er markert ferdige.
README omtaler nå 95 eksisterende 2.1-kontrakttester korrekt (tidligere
90); ingen kode ble endret etter de grønne sluttkontrollene. Testkjøringene
gjentas derfor ikke uten ny grunn. Kun dokumentasjonskontroll/staging og
lokal commit gjenstår, ingen integrert code review/done eller push.
Neste steg er separat code review av 2.2 etter ny bestilling. R2-porten før
2.3 er uendret og ingen PDF-lesbarhetsbeslutning er tatt.

Staging inkluderte også nye filer og avdekket at Git tolket ASCII-baserte
PDF-er som tekst, med strukturelle sluttmellomrom i PDF/xref. Ny
`.gitattributes` markerer bare fixture-PDF-er som binære (-text/-diff/-merge)
slik at bytes/linjeslutt og hash beholdes på tvers av checkout. Ingen PDF-byte
ble endret. Tre linjesluttmellomrom i rå dev-logg ble fjernet. Staged/commit
whitespacekontroll gjentas etter denne rene repo-/loggpresiseringen.
