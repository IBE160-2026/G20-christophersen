# Story 5.1 — viktig prompt og delegert arbeid

Dato: 2026-10-22. Brukerbestilling: kontrollert mini-sprint med sekvensielle subagenter; implementer og uavhengig BMAD-review 5.1, deretter 5.2, valgfri 5.3 etter kapasitet. Eksisterende Story-AC, UX, arkitektur, SPEC, sprintplan og sprintstatus er autoritative. Done først etter bestått review. Ikke Epic 4, R1 eller senere stories på forskudd. Relevante tester per fase, full sluttregresjon, lokale commits uten push. Ved lav usage avsluttes naturlig checkpoint ryddig.

Orkestratorens avgrensede implementeringsoppdrag: bare Story 5.1 til in-review/review; les rendret bmad-build workflow, kompiler Epic 5-kontekst og følg plan/implementeringssteg. Skill implementering fra ny uavhengig reviewagent. Les kurs-/feedbackgrunnlag, lag viktige prosesspor og verifikasjonsbevis. Bruk eksplisitte git-add-stier, la de to eksisterende rå-session-jsonl-filene være urørt og utenfor commits.

Én kontekstsubagent fikk bare oppgaven å følge compile-epic-context for Epic 5 med epics/planningdir og eksakt output `.docs/implementation-artifacts/epic-5-context.md`. Den hadde ingen kode-/commitoppgave og opprettet ingen andre agenter. Konteksten er kontrollert og lest før implementering. Ingen samtidige subagenter.

Implementeringsplanens konkrete valg: gjenbruk eksisterende testtyper og uavhengig kravfasit. Dokumenter RT-1–19, BT-1–18, AT-1–20 og sju FR-5-eksempler ved faktisk grense. Lukk det påviste sammenkoblingshullet mellom fysisk PDF/lagret analyse og session/screening med én ny integrasjonstest for F1–F4. Produktkode, krav og kontrollporter beholdes. F3 prøves ved ren grense etter kontrollert rapport og deretter fjernet L; første mangelfulle hovedreise forblir sperret.

Kvalitetskorreksjon fra orkestrator: fulle kontroller skal kjøres sekvensielt uten Chromium/HTTP-konkurranse; behold både feilet forsøk og isolert ny kjøring, og ikke øk timeout. Dette følges ved omkjøring og senere komponentkontroll. Se arbeidsøkt og verifikasjonsrapport for faktiske utfall.
